Early, and honest about it: what works and what doesn't

A programming language for agents to write, and people to read.

AIPL is a small, statically typed systems language meant to be written by AI coding agents and read by people. Every type is written out, nothing converts implicitly, and every mistake is reported with where it happened.

(module gcd
  (import io)

  ;; Greatest common divisor. The contracts are checked on every call.
  (fn gcd [a:i32 b:i32] -> i32
    (req (and (gt a 0) (gt b 0)))
    (ens (gt res 0))
    (let x:i32 a)
    (let y:i32 b)
    (while (neq y 0)
      (let t:i32 y)
      (set! y (% x y))
      (set! x t))
    x)

  (fn main [] -> i32
    (println "gcd: {(call gcd 1071 462)}")
    (println "gcd: {(call gcd 10 0)}")
    0))

Fewer mistakes get written. The rest point at themselves.

When a model writes code, the mistakes are predictable: an operator precedence it misread, an implicit conversion, an index one past the end, a bug that crashes far from its cause. AIPL removes the room for them.

01

One way to write each thing

Prefix S-expressions: no operator precedence, no indentation rules. Every parameter, return value, local and field has its type written out, and nothing converts implicitly.

02

Checks on the parts that go wrong

Contracts (req, ens) run on every call. Array indexes are bounds-checked, integer arithmetic traps on overflow, and pointers are typed and checked, in compiled code as well as in the interpreter.

03

Errors an agent can act on

Every compile error names the file, line and column. Every crash in a compiled program prints its call chain with a position for each frame. The output is meant to be pasted straight back to the model.

One small binary, the whole loop

Write, check, test, ship. The compiler is written in AIPL, builds itself from a checked-in seed with no other toolchain, and ships as a single command.

Check and run

aipl verify checks a file without running it. aipl run builds and runs it. aipl eval -e runs an expression. aipl watch re-checks as you save. aipl lint and aipl fmt keep a codebase uniform.

Tests live in the language

(test "name" ...) items sit beside the code they test, and aipl test runs each in a fresh process. aipl doc prints any module's public functions.

WebAssembly or a native executable

aipl compile makes a .wasm module; --exe makes a native Linux executable for x86-64 or AArch64. A hello-world is about 85 KB, with no runtime to install next to it.

Sandboxed by default

A program reaches the network, other programs and the file system only through grants you give at compile or run time, per host and per program. --sandbox confines files to the directory it starts in.

Built by agents, so it is checked like it was

AIPL is designed by one person and implemented with AI coding agents; the commits say so. That is why the project leans on checking instead of on trust.

Two compilers that must agree

A Rust referee and the self-hosted compiler must accept and refuse the same programs, give the same diagnostics, and behave the same on every program in a conformance suite.

Every backend, every program

The interpreter, WebAssembly and native code must agree. Fuzzers generate and mutate programs on every push, and the optimizer is checked against itself.

The docs are tested too

Every program in the documentation verifies, every quoted error message exists in the sources, every command exists. A release is built and signed by a workflow in the open.
